# AGENTS.md

## Task Completion Requirements

- All of `swift build` and `swift test` must pass before considering code tasks completed.
- After each code change, run the smallest relevant check first; before considering the task complete, run all required checks above.
- For changes touching bundle metadata, URL handlers, or default-browser behavior, run `scripts/build-app.sh` and validate the packaged app at `.build/app/Custom-CDP-Browser.app`.
- NEVER treat `swift run` as a default-browser validation path. Use `scripts/build-app.sh` and `open .build/app/Custom-CDP-Browser.app` for that path.

## Project Snapshot

`Custom CDP Browser` is a SwiftUI macOS launcher for Gabriel's persistent Helium and Chrome CDP profiles, including default-browser link routing.

This repository is small and personal, but it controls live browser profiles. Proposing changes that improve long-term maintainability is encouraged.

## Core Priorities

1. Performance first.
2. Reliability first.
3. Keep behavior predictable under closed profiles, occupied CDP ports, DevTools failures, LaunchServices quirks, and queued incoming links.

If a tradeoff is required, choose correctness and robustness over short-term convenience.

## Maintainability

Long term maintainability is a core priority. If you add new functionality, first check if there is shared logic that can be extracted to a separate module. Duplicate logic across multiple files is a code smell and should be avoided. Don't be afraid to change existing code. Don't take shortcuts by just adding local logic to solve a problem.

## Package Roles

- `Package.swift`: Defines the macOS Swift package, executable target, resources, XCTest target, and `KeyboardShortcuts` dependency.
- `Sources/CustomCDPBrowser`: Owns the SwiftUI app, floating overlay, settings, profile definitions, CDP launching, link routing, LaunchServices integration, and launch-at-login support.
- `Tests/CustomCDPBrowserTests`: Covers routing decisions, profile lookup/defaults, CDP new-tab URL encoding, and pending-link behavior.
- `scripts/build-app.sh`: Builds the release executable and assembles the `.app` bundle with the `http` and `https` URL handler metadata.

## Link Routing and CDP Launching (Important)

This app is both a profile launcher and a default-browser handoff point. Handle this path carefully because a small local shortcut can break incoming links, open the wrong profile, lose queued URLs, or leave CDP ports in a stale state.

How we use it in this codebase:

- Profile identities, profile roots, browser app names, CDP ports, and default URLs live in `Sources/CustomCDPBrowser/CDPProfile.swift`.
- Browser startup, lock cleanup, endpoint polling, DevTools `/json/new` tab creation, and process termination live in `Sources/CustomCDPBrowser/CDPProfileLauncher.swift`.
- Incoming `http`/`https` Apple events enter through `Sources/CustomCDPBrowser/AppDelegate.swift` and are routed by `Sources/CustomCDPBrowser/LinkRouter.swift`.
- Default-browser registration lives in `Sources/CustomCDPBrowser/DefaultBrowserManager.swift`, but reliable validation depends on the bundle generated by `scripts/build-app.sh`.
